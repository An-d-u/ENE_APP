# 개발 APK와 조기 LAN 시험

마지막 대화 수정·리롤은 [사용법 및 복구 규칙](chat-actions.md)을 참조한다. 이 기능은 PC ENE와 APK 양쪽에 해당 구현을 적용한 뒤 사용한다. 기존 등록·앱 데이터는 지우지 않는다.

이 앱은 실제 ENE 대화·캐릭터·음성 연결을 구현한 개발 버전이다. 소스 자동 검증을 마쳤지만 실제 휴대폰 설치·LAN 인수는 아직 하지 않았다. 최신 커밋·APK 해시·지원 범위는 [캐릭터·음성 검증 기록](media-support.md)을 참조한다. 아래 합성 응답 시험으로 기본 연결을 먼저 확인한다.

## 빌드

공개 저장소는 소스와 빌드 안내만 제공하며 완성 APK·Core·SDK·모델은 제공하지 않는다. 사용자가 [Live2D 공식 SDK 페이지](https://www.live2d.com/en/sdk/download/web/)에서 약관을 확인한 뒤 **Cubism Core for Web → Cubism 5.2** 항목의 파일을 직접 저장하고 `app/src/main/assets/character/lib/live2dcubismcore.min.js`에 배치한다. **Cubism 5.2 (Legacy URL)**도 같은 파일이다. 원본 고지를 유지한다. 전체 SDK는 필수가 아니며, 보유한 SDK의 `Core/live2dcubismcore.min.js`를 쓸 때도 아래 해시가 일치해야 한다. SDK는 저장소 밖이나 제외된 `local-sdk/`에 보관한다.

검증된 Core SHA-256은 `25ae938cb4fe282ce189b357bcc97e603d1e1f7ec78bf04150d401c23cdc792f`, 크기는 207,155바이트, Core API 버전은 `83951616`(5.1.0)이다. 제품 표기 Cubism 5.2와 Core 자체 버전은 다르다. 2026-09-17에 공식 두 경로의 해시를 대조했다. [공식 다운로드 안내 데이터](https://cubism.live2d.com/sdk-web/js/download.js)의 최신 SDK R5 또는 Core Latest/Cubism 5.3을 호환 버전으로 가정하지 않는다. 다른 버전이면 호환성 검토와 manifest 갱신이 필요하다. 검사를 끄거나 비공식 미러를 사용하지 않는다. Core 분리만으로 확장성 앱의 출시 허가가 해결되지는 않는다.

```powershell
.\gradlew.bat :app:verifyLocalCore --offline --dependency-verification strict --console=plain
.\gradlew.bat :app:testDebugUnitTest --offline --dependency-verification strict --console=plain
```

JVM 소스 검사는 Core 없이도 가능하지만 APK/AAB의 assets를 합치는 단계는 Core 누락·해시 불일치를 차단한다. `--offline`은 의존성 캐시가 준비된 환경용이다. 처음 빌드할 때 필요한 의존성을 받으려면 이 옵션만 생략하고 strict 검증은 유지한다. Core는 어느 경우에도 자동 다운로드하지 않는다.

JDK 21, Android SDK 36/Build Tools 35.0.0과 공식 의존성 캐시가 필요하다. 로컬 SDK 주소는 Git에서 제외된 `local.properties`로 관리한다. 버전 잠금과 해시 검증을 끄지 않는다.

```powershell
.\gradlew.bat :app:assembleDebug --offline --dependency-verification strict --console=plain
```

결과는 `app/build/outputs/apk/debug/app-debug.apk`다. APK·빌드 캐시·개인키·등록 파일은 커밋하지 않는다. ENE_APP과 PC ENE는 각각 독립 저장소다. 두 저장소를 같은 상위 폴더의 `ENE`, `ENE_APP`에 배치했다면 각 저장소 루트에서 해당 빌드 명령을 실행한다. 보관한 정리 전 저장소는 개발·push에 사용하지 않는다.

## 단말 선택과 설치

사용자가 시험용 Android 단말 하나를 선택하고 설치에 동의한 뒤에만 실행한다. 기존 같은 패키지의 데이터가 있으면 삭제/초기화를 자동 수행하지 않는다. 단말 일련번호·개인 대화·QR·토큰을 문서나 Git에 남기지 않는다.

```powershell
adb devices -l
adb -s <선택한-단말> install -r app/build/outputs/apk/debug/app-debug.apk
```

## 같은 개인 LAN에서 기본 연결 확인

1. PC의 정리된 ENE 저장소 루트에서 `.venv\Scripts\python.exe -m tools.companion_smoke`를 실행한다. 가상환경을 다른 경로에서 옮겼다면 먼저 현재 경로에서 다시 생성한다. 이 도구는 합성 대화와 임시 등록만 쓰며 실제 AI·기억을 호출하지 않는다.
2. PC(유선 가능)와 휴대폰을 같은 개인 LAN에 연결한다. 공유기의 기기 격리/게스트 Wi-Fi는 통신을 막을 수 있다.
3. 앱에서 QR 연결 → 카메라 권한 허용 → PC QR 스캔 → PC에서 명시 승인한다. 승인 전 앱 등록이 생성되지 않는지 확인한다.
4. 새로 만든 중립 시험 문장을 전송한다. 앱 대화와 PC의 가상 응답 계수가 한 번씩만 증가하는지 확인한다. 실제 개인 대화는 시험 자료로 쓰지 않는다.
5. 앱 배경/전경 복귀, 회전, 연결 단절/복구에서 전체 대화·초안·중복 전송 여부를 확인한다. PC를 다시 실행하면 새 실행/등록 상황에 맞게 QR을 재발급할 수 있다.
6. 권한 거절 후 재시도/앱 설정 복구, QR 만료/승인 거절, 주소 후보 실패, 잘못된 인증서 차단, 주소만 수정할 때 신뢰 유지도 확인한다.

방화벽 때문에 막히면 개인 네트워크 프로필·해당 실행 파일/포트·로컬 서브넷만 범위를 정해 사용자에게 확인받는다. 방화벽 전체 해제·공유기 포트 포워딩·Tailscale 설치는 이 시험에 포함하지 않는다.

계측 시험도 선택한 시험 단말에서만 실행한다. 시험 코드는 아직 실제 단말에서 실행하지 않았다.

```powershell
.\gradlew.bat :app:connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=dev.ene.companion.TokenStoreTest,dev.ene.companion.PairingPermissionTest --offline --dependency-verification strict --console=plain
```

연결된 단말이 여러 개면 선택을 확정하고 해당 Gradle 실행에만 ANDROID_SERIAL을 지정한다. 권한 설명 UI 시험은 OS 권한 대화상자와 카메라 수동 시험을 대체하지 않는다.

## 이후 실제 ENE 미디어 확인

2026-09-22 보완 코드를 사용할 때에는 PC 코드도 같은 보완 버전으로 통합한 뒤 ENE를 재시작하고,
아래 절차에 따라 사용자가 새 개발 APK를 업데이트한다. 기존 앱 등록·데이터를 지우지 않는다.
PC의 TTS → 재생 기기에서 저장한 선택은 다음 발화부터 적용되며, 휴대폰 선택 실패 시 PC로 소리가 새지 않아야 한다.
PC 설정과 폰 연결 상태의 원인 설명을 함께 확인한다. 원본 APK는 업데이트 전에 로컬에 보존한다.

기본 LAN 확인을 통과한 뒤 별도로 수행한다. PC는 로컬 `main`의 실제 ENE를 실행한다. 사용할 시험 모델의 권리와 AI/TTS 제공자·비용을 먼저 확인하고, 실제 대화가 없는 시험 환경에서 중립 문장만 사용한다.

1. PC에서 동반 앱 서버를 켜고 새 QR로 폰을 승인한다. 현재 대화 동기화 뒤 PC와 폰에서 각각 보내도 접수·응답이 중복되지 않는지 확인한다.
2. PC에서 지원 Live2D 모델을 선택하고 폰 표시·표정·모션·입 모양을 확인한다. 공통 설정을 양쪽에서 조정하고 충돌·취소·모델 교체 뒤 최신 값이 유지되는지 검사한다.
3. 쓰다듬기를 PC/폰에서 각각 시도하고 정상 종료당 최대 한 번 기록되는지 확인한다. 동시에 시작하거나 회전·단절해도 중복 기록이 생기지 않아야 한다.
4. 전경 폰의 음성 출력, 홈/잠금·통화·블루투스·오디오 포커스를 확인한다. 폰 재생 시작 뒤 단절된 발화는 PC에서 다시 나오지 않고, 다음 발화부터 자동 선택되는지 구분해 기록한다.
5. 등록 해제·재등록 뒤 이전 모델 캐시가 제거되는지, 새 연결의 모델을 다시 받는지 확인한다. 삭제 오류가 나면 앱을 다시 열고 재시도하며 앱 데이터 초기화로 우회하지 않는다.

계측 시험의 캐릭터·음성 코드는 빌드만 확인했다. 실제 WebGL·AudioTrack·터치·발열 검증은 수동 인수와 함께 별도로 실행한다. 자동 검사 성공을 실제 소리·화면의 성공으로 기록하지 않는다.

## 현재 결과

### 연결 복구 지원판 (2026-09-28)

이 절은 아래 확대·선명도 보완판 이후 추가된 연결 기능이다. PC ENE와 앱을 모두 대응 버전으로 맞춰야 PC 주소 자동 탐색이 동작한다. PC에는 `zeroconf==0.151.3` 의존성이 추가되며 기존 Core·모델을 다시 받지 않는다. 작업 브랜치의 변경을 main에 자동 반영하거나 push하지 않는다.

1. 기존 앱 데이터를 유지한 채 사용자가 빌드한 APK로 업데이트한다. 최초 등록은 QR과 PC 승인을 사용한다.
2. 같은 등록을 유지한 PC의 재시작 후에는 저장 주소부터 재접속한다. 주소가 바뀌면 같은 Wi-Fi에서 자동 탐색을 시도한다. HTTPS 조회·WSS·전체 대화 동기화까지 끝나야 성공 주소로 저장한다.
3. PC는 유선이어도 되지만 휴대폰과 기기 간 통신 가능한 같은 개인 LAN이어야 한다. UDP 5353 멀티캐스트나 게스트 격리, 기존 TLS 포트 차단으로 탐색/연결이 실패할 수 있다. 방화벽·공유기 설정을 자동 변경하지 않는다.
4. 자동 탐색이 안 되면 `주소 수정`으로 현재 PC 주소를 입력한다. 이때 기존 PC 인증서를 유지한다. 앱 재설치·데이터 삭제·새 QR 등록부터 시도하지 않는다.
5. `연결 진단`에서 현재 단계와 마지막 실패 단계·고정 코드를 확인한다. 주소 저장 실패 알림은 현재 연결 실패와 다르다. Android 종료 사유는 참고 정보이며 최초 페어링 후 앱이 닫힌 원인을 확정하지 않는다.

자동 탐색은 전경에서 최대 8초씩, 시작 간격 최소 30초로 제한한다. 결과는 최대 8개이고 기존 등록의 인증서와 일치해야만 토큰을 보낸다. VPN·IPv6 전용·LTE/5G·Tailscale 자동 탐색은 이번 지원 범위가 아니다. 수동 주소 연결은 유지한다.

미실행 인수 항목: 실제 PC/폰 장시간 오프라인 복귀·공유기 DHCP 주소 변경·Wi-Fi 교체·같은 LAN의 다른 PC 광고·최초 페어링 후 종료·큰 글자와 회전·Android 26–33/34 이상 NSD 정리. 설치/계측 실행과 Live2D 출시 허가 검토는 별도다. 시험 자료에는 실제 대화·기기 식별자·QR·토큰을 남기지 않는다.

검증한 코드 조합은 ENE `ff31e89`, ENE_APP `c2a0009`다. Python 3.12 전체 4,340개 통과(기존 Windows 심볼릭 링크 권한 제한 1개 제외), Python 3.11 집중 68개 통과, Android 전체 JVM 319개 통과(실패·오류·제외 0). offline strict lint·개발/계측 APK 빌드 성공이며 lint 오류 0, 기존 경고 4개는 유지된다. 통합 리뷰에서 발견한 Android 13 탐색 잠금과 등록 해제 직후 광고 경합은 회귀 검사로 수정했다.

최종 로컬 개발 APK: `app/build/outputs/apk/debug/app-debug.apk`, 38,029,826바이트, SHA-256 `17ec6f2600b5a3a24c686454242dd00244641d1a235cd3bee86dbc13e1ba6d71`.
계측 APK: `app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk`, 1,167,127바이트, SHA-256 `d7e21e829add1b2d6a314f09a85a46354a8d87f9450cc8711b048bfbfd2bb01e`.

두 서명은 기존 개발 APK와 동일하고, APK 내부 Core 해시도 기존 로컬 Core와 일치한다. APK·Core·모델은 Git에서 제외하며 공개 업로드하지 않았다. 아래 과거 APK 해시는 새 연결 복구 APK 식별자가 아니다.

### 확대·선명도 보완판 (2026-09-28)

`휴대폰 표시 설정`의 확대는 50–600%, 가로·세로 위치는 −300–400%다. 확대 후 위치를 옮겨 보고 싶은 부분을 맞춘다. 기존 저장값은 그대로 복원하며, 화면 밖으로 이동한 캐릭터는 `기본 배치 복원`으로 크기 100%·가로/세로 50%로 되돌릴 수 있다.

고밀도 화면에 맞춰 내부 그리기 해상도를 높이되 픽셀 예산과 GPU 한도를 적용한다. 확대 조작으로 버퍼나 모델을 다시 만들지는 않는다. 원본 텍스처·마스크 자체의 흐림과 단말 발열은 별도 확인 대상이다. 자세한 한도와 수명은 [캐릭터 실행부 안내](character-runtime.md#휴대폰-그리기-밀도)에 있다.

기존 개발/계측 APK는 새 빌드 전에 Git 제외 위치로 복사하고 SHA-256을 비교해 보존한다. **구 APK로 되돌리기 전에는 기존 조절 범위(크기 50–200%, 위치 0–100%)로 저장하거나 기본 배치를 복원한다.** 새 범위 값을 저장한 채 이전 APK를 쓰면 읽기 실패가 발생할 수 있다. 앱 데이터는 자동 삭제하지 않는다.

아래 실제 단말 시험은 이번에도 실행하지 않는다. 확대된 모델의 선명도·터치·회전·큰 글자·장시간 발열은 단말에서 별도로 확인해야 한다. 자동 검사와 계측 APK 컴파일은 단말 시험 성공을 뜻하지 않는다.

소스 조합은 ENE `7068a8e`, ENE_APP `a277e2c`다. `codex/companion-character-layout` 작업 브랜치에서 검증했으며 이번 변경의 main 통합·push·단말 설치·공개 릴리스는 하지 않았다.

- ENE Python 3.12: 전체 4,327개 통과, 기존 심볼릭 링크 권한 제한 검사 1개 제외. 새 검사를 건너뛰도록 바꾸지 않았다.
