# 캐릭터 파일과 WebView 경계

확인일: 2026-10-10. 안전한 WebView API를 지원하면 `character_v1`과 `character_controls_v1`을 협상한다. 캐릭터·립싱크·공통 설정·쓰다듬기 연결에 휴대폰 로컬 배치 저장, 확대·밀도 보완, 화면 복귀 시 모델 보관을 추가했다. 아래 C3/C4/D2/D3 수치는 각 단계 당시 기록이다. 이번 변경의 실제 단말 설치·계측 실행·WebGL 모델 시험은 하지 않았다.

## 휴대폰 배치와 표시 수명

`휴대폰 표시 설정`에서 크기 50–600%, 가로·세로 위치 −300–400%를 조절한다. 크기 100%는 현재 표시 영역에 여유를 두고 맞춘 크기이며 모델의 원래 크기와 다르다. 위치는 표시 영역에 대한 모델 중심의 비율이다. 중심을 화면 밖으로 옮겨 확대된 얼굴이나 상체를 맞출 수 있다. 캐릭터가 보이지 않을 만큼 이동하면 `기본 배치 복원`을 사용한다. 움직임의 위치 변화는 이 배치를 기준으로 적용하며 PC 창의 크기·위치는 변경하지 않는다.

배치는 앱 수명의 컨트롤러가 `noBackupFilesDir/character_presentation/placement.json`에 원자 저장한다. 마지막 조절 뒤 250ms를 기다려 변경을 합치고 손을 떼거나 시트를 닫으면 즉시 저장 요청한다. 동시에 두 번 쓰지 않으며 오래된 완료가 최신 미저장 상태를 덮지 않는다. 실패하면 화면의 조절값과 마지막 정상 파일을 유지하고 `저장 재시도`를 제공한다. 최초 읽기에 실패한 파일은 단순 읽기만으로 덮어쓰지 않는다.

앱 재시작·재접속·등록 해제에도 마지막 저장값은 유지된다. 모든 PC·모델에 같은 휴대폰 배치를 사용한다. 앱 삭제·앱 데이터 초기화에는 보존을 보장하지 않으며 클라우드 백업 대상도 아니다. `기본 배치 복원`은 크기 100%, 가로·세로 50%를 저장한다.

저장 형식은 `version: 1`을 유지하며 이전 값은 재해석하거나 자동 확대하지 않는다. 문자열 숫자·비유한 값·범위 밖·추가 필드는 계속 거부한다. **이전 APK로 되돌리기 전에는 크기 50–200%, 위치 0–100% 안으로 조절하거나 기본 배치를 복원하고 `저장됨`을 확인한다.** 이전 APK는 확장된 저장값을 읽지 못할 수 있다. 데이터 삭제로 해결하지 않는다.

캐릭터는 [전체 화면 배경](mobile-chat-layout.md)을 사용하며 대화창 높이·키보드 여백과 분리한다. 같은 인증 연결의 대화 동기화나 QR 화면 표시만으로는 WebView 소유권을 바꾸지 않는다. 유효 QR로 새 페어링을 시작하면 이전 모델은 폐기한다. 숨김은 네이티브 표시·터치·접근성과 모델 자동 갱신·앱 ticker·추적 RAF·제스처 타이머를 중지한다. 일시 연결 종료와 실제 표시 폐기는 아래 규칙으로 구분한다. 회전으로 Activity가 바뀌면 새 뷰를 만들 수 있지만 배치는 앱 상태에서 복원한다.

복귀 시 표정 현재값·확정 설정·현재 입 모양만 복원하고 숨김 중 일회성 제스처나 음성 시작을 재생하지 않는다. 같은 모델의 스냅샷은 SDK 모델 객체와 불변 자산 mount를 재사용한다. 진입점의 모델 목록 JSON 재조회와 전체 모델 재생성은 구분한다. 스냅샷 읽기 중 들어온 더 최신 표정은 하나만 보관해 적용하며 이전 세대가 새 세대의 상태를 지우지 못한다.

PC에서 확정한 움직임 설정 20개는 기존 동기화 경로를 사용한다. `캐릭터 공통 설정`은 계속 PC에 저장되며 `휴대폰 표시 설정`은 로컬 저장소만 사용한다. 미저장 PC 미리보기·PC 마우스 좌표·PC 창 배치를 새로 전달하지 않는다. 내부 `presentation` 명령은 정확한 키·숫자·boolean과 2KiB 상한을 검사하며 원격 프로토콜이나 임의 JavaScript 실행 API를 추가하지 않는다.

## 화면 잠금·앱 복귀와 모델 보관

준비된 모델과 살아 있는 WebView가 있으면 잠금·홈 이동·짧은 앱 전환·같은 PC 재연결에서 하나만 숨겨 보관한다. 연결 세션과 표시 소유자를 분리했으며, 배경에서는 연결·다운로드·음성·세션 타이머를 종료한다. 보관만을 위해 백그라운드 통신을 유지하지 않는다.

복귀하면 인증과 대화 동기화를 마친 새 연결에서 manifest와 캐시 무결성을 다시 확인한다. 같은 등록·모델·자산 묶음이면 기존 모델 객체와 뷰의 캐시 핀을 재사용한다. 모델 자산은 다시 받지 않지만 최신 상태 확인은 생략하지 않는다. 보관 중 안내는 `캐릭터 상태를 갱신하고 있습니다.`이며 새 설정·표정 적용이 끝난 뒤에만 보여 준다. 네이티브 표시 권한도 검사하므로 오래된 Compose 화면 상태만으로 다시 나타나지 않는다.

문서 UUID와 별도로 앱 내부 표시 세대를 검사한다. 이전 연결·스냅샷의 늦은 완료, 오류, 입력은 새 표시를 바꾸지 못한다. 표정 현재값만 복원하고 숨김 중 제스처·쓰다듬기·음성 시작을 몰아서 재생하지 않는다. PC 주소나 실행 세대가 바뀌어도 등록 신뢰와 모델이 같으면 재사용하지만, 이전 연결의 순번이나 음성 상태를 새 연결에 넘기지는 않는다.

등록 해제·유효 QR 페어링 시작·신뢰 검증 실패·미지원·모델 변경·렌더러 사망·명시적 캐릭터 재시도에서는 보관을 해제한다. 등록 캐시를 지우기 전 다운로드를 회수하고 뷰·열린 스트림의 핀을 반환한다. 정리 실패 시 기존 등록을 보존하고 오류를 알린다. 초기 로딩이 완료되지 않은 모델은 보관 대상으로 취급하지 않는다.

**OS가 Activity·앱 프로세스·WebView 렌더러를 실제로 종료하면 새 로딩이 필요하다.** 화면 잠금만으로 이루어지던 불필요한 재생성을 줄이는 변경이지, 메모리 회수 뒤까지 모델을 유지하는 기능은 아니다. 저장한 크기·위치·대화창 높이는 기존 저장 정책을 그대로 따른다. 실제 기기의 복귀 시간·GPU 메모리·발열은 미검증이다.

## 휴대폰 그리기 밀도

휴대폰에서만 화면 픽셀 밀도에 맞춰 Pixi `autoDensity`를 사용한다. 모델 맞춤·위치·모션·쓰다듬기는 CSS 좌표를 유지한다. 확대가 600%여도 화면 버퍼를 추가로 6배 키우지 않으며, 배치 변경 때문에 모델이나 WebView를 다시 만들지 않는다.

목표 밀도는 1–3배이고, 캔버스 버퍼는 총 4,194,304픽셀·한 변 4096픽셀과 GPU의 텍스처/렌더버퍼/뷰포트 한도 중 작은 값으로 제한한다. 반올림 뒤에도 이 한도를 검사한다. 큰 영역에서는 최종 밀도가 1 미만일 수 있다. GPU 한도를 읽지 못하면 승격하지 않고 최대 1배로 그린다. 이 예산은 주 캔버스에 관한 것이며 전체 GPU 메모리·발열의 상한이 아니다.

처음에는 1×1 버퍼로 GPU 한도를 확인하고 유효한 표시 크기를 적용한다. phone 전용 크기 변경 경로 하나만 사용하며 같은 크기·밀도에는 다시 할당하지 않는다. 회전 중 너비를 먼저 바꾸면서 일시적으로 예산을 초과할 경우에만 물리 1×1을 거쳐 최종 크기로 변경한다. 숨김·0 크기에서는 마지막 버퍼를 유지하고, 복귀 때 최신 크기·밀도를 적용한다. 종료 시 밀도 감지 리스너도 제거한다. 초기화·크기 적용 실패는 기존 캐릭터 오류로 알리고 자동 재시도 루프를 만들지 않는다. PC 초기화와 해상도는 변경하지 않는다.

화면 버퍼 보완은 원본 텍스처나 Live2D 마스크의 해상도를 늘리는 처리가 아니다. 확대 시 남는 흐림·선명도·발열은 실제 모델과 단말에서 따로 확인해야 한다.

## 파일 받기와 보관

`CharacterRepository.create()`는 Application에서 한 번 생성해 공유한다. 파일은 `noBackupFilesDir/character` 아래에 보관한다. 서버 ID·CA SHA-256·기기 ID·등록 세대를 묶은 해시로 서버를 분리하며 토큰·LAN 주소는 캐시 이름이나 manifest에 넣지 않는다.

현재 연결에서 새 manifest를 받기 전에는 남은 파일을 표시하지 않는다. 스냅샷은 공개 필드만 남기고 모델 버전, 자산 목록, 매개변수 범위, 설정을 검증한다. 목록 256KiB, 파일 32MiB, 모델 합계 128MiB, 256개 파일, PNG/JPEG 한 변 8192픽셀 한도를 적용한다. 이미지 검사는 픽셀 할당 전 헤더 크기 검사이며 실제 SDK 디코딩 성공을 보장하지 않는다.

캐시는 전체 256MiB·2개 버전 이내다. 받기 시작할 때 파일과 manifest의 예상 크기를 예약하므로 `.part`도 한도에 포함된다. 사용 중인 뷰와 열린 읽기 스트림은 캐시 핀을 소유한다. 미사용 버전만 회수하고, 공간이 부족하면 실패한다. 다른 앱의 캐시를 지우거나 OS 저장소 회수를 강제하지 않는다.

파일별 크기·SHA-256을 검사한 뒤 이름을 바꾸고, 전체가 검증되면 manifest를 기록·동기화한 다음 폴더를 원자적으로 활성화한다. 재시작 때도 손상 여부를 확인한다. 취소·연결 세대 변경·모델 교체는 해당 받기 작업과 임시 파일만 정리한다. 삭제는 이름을 확인한 앱 전용 하위 폴더에 한정하며 링크를 따라가지 않는다.

`CharacterMediaTransport`는 현재 WSS의 TLS/CA/서버 이름 검증을 빌리고 네이티브 HTTPS 요청에만 인증 헤더를 넣는다. 전송은 한 번에 한 요청이며 자산을 순차적으로 받는다. 압축·리다이렉트·Range·query·Origin을 사용하지 않고 자동 재시도하지 않는다. 파일 요청은 유휴 10초/전체 60초, 모델 전체는 5분을 제한한다. 취소는 대기 중인 소켓 읽기도 종료한다. 음성 전송 객체와 수명은 분리한다.

## 캐릭터 전용 WebView

출처는 `https://appassets.androidplatform.net`, 문서는 `/character/index.html` 하나다. 내장 스크립트·스타일의 고정 목록과 현재 manifest에 있는 `/models/{model_version}/assets/{asset_id}`만 네이티브가 제공한다. 다른 요청은 403이며 네트워크로 넘기지 않는다. 토큰이나 PC 주소를 JavaScript에 주입하지 않는다.

파일/content 접근, mixed content, 웹 저장소, 서비스 worker 통신, 외부 이동, 새 창, 다운로드, 권한 요청을 막는다. CSP도 적용한다. WebMessageListener 지원 여부, 정확한 출처, 주 프레임, 문서 UUID, 2KiB 메시지 크기와 알려진 유형을 검사한다. 안전한 메시지 API가 없으면 캐릭터만 사용할 수 없게 하고 `addJavascriptInterface`로 대체하지 않는다.

새 문서는 네이티브의 initialize를 받아야 상태를 수락한다. manifest 256KiB에 문서 세대 봉투용 256바이트를 별도로 허용한다. 초기화 무응답은 10초 뒤 실패하고, 렌더러 종료는 스트림·핀·브리지·뷰를 정리해 실패를 알린다. 자동으로 반복 생성하지 않는다. C4 화면이 이 상태를 표시하고 사용자 재시도를 제공한다.

## 채팅 화면과 재생 위치

캐릭터 전용 AndroidView 위에 반투명 Compose 대화창을 겹치며 채팅 초안·목록은 유지한다. 작은 화면·큰 글씨에서는 대화창의 표시 높이를 보정하고 키보드 여백은 전경에만 적용한다. 상태 문구를 누르면 로딩·미지원·표시 실패의 전체 사유와 재시도 버튼에 접근한다. 렌더러 실패는 채팅 연결이나 음성 재생을 끊지 않는다.

연결이 바뀌면 새 manifest를 받고, 모델 변경이 연속되면 앞 HTTP를 취소·회수한 뒤 마지막 요청 하나만 처리한다. 다운로드/회전 중의 일회성 제스처는 번호만 관찰하고 나중에 몰아서 실행하지 않는다. 표정 현재값과 확정 설정은 스냅샷으로 복원한다. 새 뷰에는 현재 위치를 주입하지만 오디오 시작을 재전송하지 않는다.

휴대폰 출력은 AudioTrack이 소비한 PCM 위치와 음량을 사용하고 원격 echo는 적용하지 않는다. PC 출력은 PC 오디오 장치 위치를 최대 10Hz로 전달받는다. 시간을 추정해 앞당기지 않으며 750ms 갱신이 없으면 입을 닫는다. 이전 발화의 늦은 종료가 새 발화를 닫지 못하도록 식별자를 검사한다. 공개 대화 메시지에 속한 음성만 캐릭터와 연결한다.

## 공통 설정의 편집 범위

공통 설정 경계는 허용 키와 현재 모델 범위를 검증하고, 저장 결과를 받은 뒤 새 manifest로 확정한다. 전송 결과가 불명확하면 자동으로 다시 저장하지 않는다. PC의 기존 보호 정책과 맞춰 `ParamEye`, `ParamMouth`, `ParamJaw`, `ParamTongue`, `ParamBrow`, `ParamAngle`, `ParamBody`, `ParamBreath`, `ParamArm`, `ParamHand`, `ParamShoulder`, `ParamLeg`로 시작하는 값은 직접 수정하지 못한다. 장식값만 수정하며 눈깜빡임·움직임 강도는 별도 공통 설정으로 다룬다.

D2 집중 검증은 `CharacterControlsTest` 8개와 `ExtensionCodecTest` 4개, 총 12개가 통과했다. 아직 모바일 설정 화면과 `character_controls_v1` 광고는 켜지 않았으며 D3/D4에 남아 있다. 아래 전체 빌드 결과는 C4 시점이다.

## 쓰다듬기 입력 연결

입력은 PC가 확인하는 시작·갱신·종료·취소로 전달한다. 폰은 강도 갱신을 최대 10Hz로 합치고, 정지한 포인터도 500ms마다 실제 입력을 갱신한다. 입력이 2초 동안 끊기거나 회전/숨김/모델 교체/표시 실패가 발생하면 정상 종료 대신 취소한다. 시각 효과가 되돌아와도 새 입력이나 횟수 증가 요청을 만들지 않는다. PC가 수락한 세션의 정상 종료만 기존 기록 경로에 반영한다.

D3 캐릭터 계열·쓰다듬기·확장 계약 JVM 검증은 15개 클래스 75개 시험이 통과했다. 공유 실행부의 쓰다듬기·모션 상태·호스트·진입점 4개 해시를 갱신했고 라이브러리 원본은 그대로다. 설정 화면과 `character_controls_v1` 광고는 D4에 남아 있으므로 이 기록을 실기기 기능 인수 완료로 해석하지 않는다.

## 실행부 출처와 빌드 고정

PC의 `tools/export_companion_character.py`는 명시 목록 21개 중 Core를 제외한 소스·라이브러리·고지 20개와 manifest만 `app/src/main/assets/character`로 복사한다. Core는 사용자가 공식 SDK를 직접 받아 설치한다. 정상적인 기존 로컬 Core는 내보내기가 덮어쓰지 않는다. 함께 보관한 `import-manifest.json`으로 독립 앱 checkout에서도 목록과 SHA-256을 검사한다. Core 없이 JVM 소스 검사는 가능하지만 APK/AAB 빌드는 Core 설치와 해시 검증이 필수다. 앱 쪽 소스 복사본은 PC 원본 변경 후 내보낸다. 모델·일반 설정·대화 파일은 내보내지 않는다.

Pixi 7.3.0, pixi-live2d-display 0.4.0-cubism4, 고정 Cubism Core의 출처·원문 고지는 가져오기 manifest와 `notices/`에 있다. 기존 PC 조합을 유지했으며 실제 기기의 WebGL 호환성과 공개 배포 권리 검토는 별도 확인 사항이다. SDK/모델 재배포가 자동 승인됐다는 의미가 아니다.

WebKit은 계획대로 1.15.0으로 고정했다. [공식 변경 이력](https://developer.android.com/jetpack/androidx/releases/webkit#1.15.0)과 [안전한 메시지 API](https://developer.android.com/reference/androidx/webkit/WebViewCompat)를 기준으로 사용한다. 기존 잠금·해시는 바꾸지 않고 아래 신규 파일만 추가했으며 Google Maven HTTPS 원본을 다시 읽어 SHA-256을 대조했다.

| 공식 Maven 파일 | SHA-256 |
| --- | --- |
| `androidx/webkit/webkit/1.15.0/webkit-1.15.0.aar` | `241c90aac937b6562592976da5cc73100538bf255000f490ed37296da1773960` |
| `androidx/webkit/webkit/1.15.0/webkit-1.15.0.module` | `c5d34727dfb45d6df66faf1d74927a7f118808a48ef44d0d9f33ab8d1c8df4fe` |
| `androidx/annotation/annotation-experimental/1.3.0/annotation-experimental-1.3.0.module` | `5eebeaff01d042e06dcf292abf8964ad391e4b0159f0090f16253d6045d38da0` |

## 검증 명령

2026-09-28 확대·밀도 보완 검증 결과는 [빌드 기록](build-and-install.md#확대선명도-보완판-2026-09-28)에 있다. 아래 C4 수치는 과거 단계의 기록이며 최신 전체 검사 수치와 구분한다.

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest --offline --dependency-verification strict --console=plain
```

ENE 저장소의 Python 환경에서 실제 렌더러 검사 도구를 실행할 수 있다.

```powershell
python -m tools.companion_character_viewport_probe --browser "<설치된 Chrome 또는 Edge 실행 파일의 절대 경로>"
```

도구는 새 임시 프로필과 루프백 서버의 고정 허용 파일만 사용한다. Core·모델·사용자 브라우저 프로필을 읽지 않는다. DPR 1/3/1.25의 실제 버퍼와 합성 크기 전환의 중간 canvas/GL 픽셀 예산을 검사한다. 종료 코드 0은 통과, 1은 검사 실패, 2는 브라우저/WebGL을 사용할 수 없어 미검증이라는 뜻이다. 이 결과도 Android 단말의 실제 모델 품질·발열 검사를 대신하지 않는다.

JVM 시험은 합성 manifest/바이트, 임시 폴더, 로컬 TLS 시험 서버, 정책 검사만 사용한다. 캐릭터 계측 테스트 4개는 컴파일만 했고, 실제 캐릭터 표시·손가락 입력·회전·접근성·GPU/음성 동작은 단말 시험 전까지 미검증이다. 빌드 산출물은 Git에 포함하지 않는다.

최종 실행: 전체 JVM 39개 클래스/210개 시험 통과, 실패·오류·제외 0. C4에서 추가한 시험은 22개다. offline strict Lint/debug APK/계측 APK 빌드도 통과했다(52초). Lint는 오류 0/경고 28개이며 기존 의존성 갱신·아이콘·남은 공간 조회·KTX 안내 외에 화면 높이 API 제안 1개가 있다. 이 제안은 D4 통합 UI 검토에 남겼다. 원본 Pixi 파일에 있는 공백 4곳은 출처 해시 보존을 위해 수정하지 않았으며 C4 변경분의 공백 검사는 통과했다. 공유 실행부 20개 파일은 C3의 고정 해시를 그대로 사용한다.

C4 개발 APK SHA-256: `4508645a53e4808b3c877a7f0cce152782aa869d437260aeb6dee91a847a52ef`. 개발 산출물의 식별값이며 배포 서명·단말 설치·사용자 인수 완료를 뜻하지 않는다.
